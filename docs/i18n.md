# Internationalization

TurkDemy enables Django `LocaleMiddleware` and supports:

- English (`en`)
- Persian (`fa`)
- Turkish (`tr`)
- Arabic (`ar`)

`LOCALE_PATHS` points to the repository-level `locale/` directory. Product URLs use
Django `i18n_patterns` where localization is enabled.

## Application-wide localization contract

`I18N-001` applies to every intentionally translation-enabled TurkDemy product page,
including public, account/authentication, customer Request/workspace, messaging,
Agent/staff and shared UI. RTL direction alone is not considered localization.

Interface copy uses Django gettext. Translation-enabled templates must use
`trans`/`translate`/`blocktrans`, while Python presentation strings use gettext or lazy
gettext. TurkDemy-owned JavaScript receives localized copy from server-rendered data
attributes instead of embedding English UI fallbacks.

## Structured/model values

Database-localized fields (`name_en`, `name_fa`, etc.) are separate from gettext UI
translations. Visible structured values use the active locale when populated and fall
back to canonical English when the requested value is genuinely absent. TurkDemy does
not generate or guess missing domain-data translations.

The canonical helper is `apps.core.localization.localized_value()`. Models commonly
expose `localized_name` / `localized_description`; the global `localized` template
filter is available for other objects/dictionaries.

Do not directly render `.name_en`, `.description_en`, `.question_en` or `.answer_en`
on a translation-enabled product page merely as a convenience. Identity/slug fields
are separate and follow their own URL contracts.

## Forms

`LocalizedFormMixin` gives Django-generated model/form labels, help text, empty labels
and selected widget presentation attributes a gettext lookup in the active locale.
Explicit lazy translations remain preferred for authored form copy.

## Exclusions

Email templates remain governed by the multilingual email/Email Preview Gallery
requirements. Django Admin, third-party UI, management-command output and internal
`admin_tools` pages are not covered unless intentionally promoted to localized product
UI. User-authored free text and historical free-text content are not machine-translated.

## Validation

`tests/test_application_localization_integrity.py` checks structured-value fallback,
translation catalogue coverage and source-level product-surface invariants.
`tests/test_searchable_multiselect.py` protects the localized JavaScript presentation
contract. When adding new translated interface copy, update all supported locale
catalogues and compile their `.mo` files.
